# VFX repair and migration preparation

Completed validation: 2026-09-07. **116 unit tests and 18 focused browser tests
passed**, plus syntax checks on 63 VFX-related files and the import-graph check.

Scope: VFX renderer, sprite/clip playback, presentation profiles, VFX styles,
asset tooling, and related tests/documentation. No spell rules, targeting data,
token placement/elevation rules, combat state, or original PNGs were changed.

## Correctness and composition

- Attachments measure the visible direct token child while the token parent stays
  on the ground. Under stays grounded; centered, above, overhead and orbit follow
  the raised body. Tests exercise the production DOM at 0, 20 and 40 feet.
- World Z drives perspective, shadow ratios and depth. Screen Z only projects
  height onto the display. Tests cover 50%, 75%, 100%, 150% and 200% zoom, with
  both an untransformed host and a transformed board; inherited zoom is canceled
  on VFX layers to prevent applying it twice.
- The fake VFX tokens container is removed. Ordering is ground 100, shadows 200,
  real tokenLayer 300, airborne 400, overhead 500, UI 600. Legacy requests for
  layer "tokens" alias to airborne. A rendered-pixel scene checks the full stack.
- Every procedural profile compiles an explicit family preset/layer.
  profile-ground, scorch and frost are ground effects; cloud, hail and weather
  are overhead. Beam art retains its full aimed path without translating the
  entire beam as a moving projectile.
- Small/medium/heavy/massive impact feedback is reusable. Major profile impacts
  use punch, bounded shake, optional 45/70 ms visual hit-stop, subtle ground light
  and a shock ring. Utility/cantrip profiles do not gain shake. Existing Fireball
  clip events retain their flash, shockwave, smoke and shake composition.
- Standard aftermath recipes cover fire, cold, lightning, acid, poison, necrotic,
  radiant and force. Existing explicit aftermath remains authoritative.
- Profile level growth is reduced from 22% to 6% per level. Visual role caps
  bound projectiles, impacts, auras, terrain and weather; template geometry
  remains unchanged. Procedural profile visuals remain fallback/accent coverage.
- Shadows support minimum opacity, minimum scale and height-dependent blur.
  Projectile defaults retain a faint high-altitude shadow.

## Assets and loading

The inventory contains 83 original PNGs plus 37 derived compatibility PNGs.
The alpha tool inspects every original and reports hashes, alpha, dimensions,
frame energy, centroid movement and edge coverage. Originals remain byte-for-byte
unchanged; tests compare their hashes against the report.

The 37 opaque black-backed sheets now resolve to RGBA compatibility copies
(76.8 MiB on disk, loaded only for selected effects).
Blessing required removal of a dark-blue matte. Measured crop metadata still
excludes legacy status borders and uneven atlas gutters. Screen blending alone
is no longer the mechanism that removes those black backgrounds.

Modern Fireball impact/aftermath use their existing transparent 6×6 sheet with
asset-owned normal blending and an impact-center anchor. Each clip locks its
starting version. Modern sheets begin loading during earlier phases; readiness
includes image.decode(). A cold, unavailable, disabled, invalid or failed modern
asset uses legacy. Late completion cannot switch or resurrect an active clip.

All Fireball phases now expose legacy/modern slots. The remaining modern slots
are deliberately empty. Non-clip sprites have a replacement registry keyed by
effect ID, independent of legacy spell-level tiers. Future assets own their frame
windows, orientation, blend mode and anchor; legacy transition maps remain local
to legacy definitions.

ALL newly remade animated artwork must be 6 columns × 6 rows / 36 frames.
Keeping a legacy asset is separately recorded from NEEDS_6X6 replacement work.
The engine still accepts arbitrary grids and measured atlases.

## Performance and modes

Full mode permits 192 regular particles and 320 dynamic detail nodes globally.
Reduced permits 48 and 96. Detail accounting includes normal particles, trails,
debris, profile scatter and hail. Debug state also reports active effects,
sprite effects and persistent statuses. At the 64-effect limit, secondary effects
are removed before normal effects; core animations already playing are retained.
If all 64 slots contain core animations, another core request is skipped with
the explicit core-capacity reason. This is a hard resource limit.

Static path CSS is cached. Attachment geometry is shared by token/layer and
invalidated by movement, size/style/elevation changes, zoom and map refresh.
The stress test repeats three Full and three Reduced cycles with 20 statuses,
ten tokens (including raised tokens), Fireball, Lightning and five particle-heavy
ground effects. All twenty distinct status sheets are decoded before the run;
the scene yields to real browser paints. The observed run used:

| Measure | Full | Reduced |
|---|---:|---:|
| Peak total scene elements | 392 | 158 |
| Peak dynamic detail nodes | 284 | 52 |
| Peak regular particles | 192 | 48 |
| Peak active effects | 31 | 31 |
| Pending renderer RAF callbacks | 1 | 1 |
| Layout reads on stable attachment frames | 0 | 0 |
| Reads after a token geometry/elevation change | 3 | 3 |
| Stale effects, timers, RAF callbacks after clear | 0 | 0 |

Measured renderer callback averages were approximately 0.48–0.55 ms, with a
9.7 ms maximum in that run. These are JavaScript callback measurements from
headless Chromium, not end-to-end GPU frame times or a hardware guarantee.
After garbage collection, JS heap growth across six cycles was about 1.9 MB;
DOM counts stayed identical across repeated cycles. The test reports heap
growth and caps it at 12 MB to catch substantial retained state. The raw metrics
are retained in [stress-metrics.json](../assets/vfx/audit/stress-metrics.json).

Reduced sequences preserve 90% of their normal duration, disable shake/hit-stop,
omit Full-only accents, shorten trails and reduce particles/debris. CSS no longer
compresses animations into 180 ms. A real 36-frame JS sprite is exercised in
Full/Reduced/Off separately from CSS.

## Validation and remaining art work

Run:

    node --test --test-isolation=none tests/vfx-*.test.mjs
    node node_modules/@playwright/test/cli.js test tests/browser.spec.mjs --grep "VFX|vfx|Fireball|fireball|Lightning|lightning|cantrip sprite|storm profiles|production token elevation|tier sprite"
    python scripts/vfx-alpha.py --audit

The tests cover production elevation, zoom invariance, rendered layer ordering
and background pixels, per-version fallback, normalized clip events, decode
failure, late-load cleanup, shared budgets, cache invalidation, modes, original
asset preservation, and existing preview/targeting integration.
Rendered-pixel coverage includes all 36 modern Fireball frames and all 37
compatibility sheets over five backgrounds, including a production token DOM.

Artwork creation is the next stage, not something completed by this repair pass.
Priority: remaining Fireball clips; Lightning Bolt; Cold/Ice; Acid; Poison;
Necrotic; Radiant; Force; Thunder; Psychic; Healing; Buffs; Debuffs; remaining
effects. The existing Fireball sheet is a derived legacy atlas with measured
boundaries, not a newly generated equal-cell sheet.

The alpha contact sheet and frame metrics expose legacy seams, uneven framing
and possible jitter. They do not prove zero jitter throughout the old library.
New art acceptance requires all 36 frames reviewed at a fixed anchor over dark,
bright, colored, transparent and actual token backgrounds, at normal and reduced
playback, checking center drift, size/rotation jumps, brightness flicker and
clipping. Do not promote a replacement solely because its grid validates.
